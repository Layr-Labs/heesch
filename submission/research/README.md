# Two folded polyiamonds with three rings

The primary 27-iamond has three complete coronas and an exact upper bound from its `F(S,4)` proof. The 16-iamond companion has the same exact ring count and a separate proof. `folds.png` shows the ring boundaries. The two sibling shapes share the first axial cut of a 53-iamond parent. Kaplan's public 16-iamond table also records the companion as `Hc = 3 Hh = 3`, entry 4 of 36. Its exact row and table digest are in `census16.json`. The author's public polyiamond index lists files through 24 cells. [Polyiamond tables](https://cs.uwaterloo.ca/~csk/heesch/iamond/) [16-iamond table](https://cs.uwaterloo.ca/~csk/heesch/iamond/16iamond_2up.txt)

From the cloned benchmark with the verifier installed, run `PYTHONPATH=. python submission/research/replay.py`. It verifies all 90 marked interfaces, the physical 53-iamond lift, both cut sequences, every full-ring placement, both partial rings, the census coordinates and the SHA-256 of each decompressed proof component. The 53-iamond parent uses a relaxed span cap only in the parent replay. Both children verify with the benchmark's default caps. `construction.json` lists the coordinate operations in execution order. Register a child after each operation by minimizing the sum of the two coordinate spans among all legal orientations and breaking ties lexicographically.

The frozen encoder produced both `F(S,4)` formulas. CaDiCaL found UNSAT, `drat-trim` verified the DRAT, and `lrat-check` verified the compact core proof for each. On the standard Linux checker installation, invoke `python -m heesch_verify submission/best.heesch --check-proof --profile record` and `python -m heesch_verify submission/research/companion16/best.heesch --check-proof --profile record` for the full formula regeneration and checker path. The challenge runner grades the primary file. Each copy of `best.heesch` refers to the proof and core files in its own directory.

With OR-Tools 9.15.6755 installed, `PYTHONPATH=. python submission/research/repack.py /tmp/heesch-fold-repack` reproduces both partial searches. `coverage.py` maximizes covered required sites on each fixed footprint. `pocket_pack.py` tries to improve the true defect by charging enclosed cells that lie outside the required halo. Both tighter bounds were infeasible for those footprints.
